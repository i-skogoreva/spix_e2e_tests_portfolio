# CLAUDE.md

Этот файл содержит руководство для Claude Code (claude.ai/code) при работе с кодом в данном репозитории.

## Обзор проекта


Фреймворк автоматизации E2E-тестирования на базе Playwright для платформы SPIX (https://go.dev.spix.ru/). Использует pytest как тест-раннер и Allure для отчётности.

## Команды

```bash
# Запуск всех тестов (результаты Allure автоматически сохраняются в allure-results/)
pytest

# Запуск конкретного тестового файла
pytest tests/test_user_authorization.py

# Запуск конкретного теста по имени
pytest -k "test_name"

# Просмотр Allure-отчёта после прогона тестов
allure serve allure-results

# Установка зависимостей
pip install -r requirements.txt

# Установка браузеров Playwright
playwright install chromium
```

## Архитектура

Проект построен по паттерну **Page Object Model** с использованием pytest-фикстур:

```
conftest.py (фикстуры: page, get_cookies, authorized_user)
  → tests/          (тест-кейсы с декораторами Allure)
    → pages/        (page-объекты, наследуются от BasePage)
      → locators/   (классы с CSS-селекторами, без логики)
  → data/           (эндпоинты, учётные данные через dataclasses)
  → utils/          (ассерты, генераторы на базе Faker)
  → docs/           (документация тестов: для каждого test_*.py — соответствующий test_*.md)
```

**Основные соглашения:**
- `BasePage` (`pages/base_page.py`) содержит общие методы взаимодействия с Playwright — все page-объекты наследуются от него
- Локаторы — чистые CSS-селекторы, собраны в классах в директории `locators/`
- Тестовые данные загружаются из `.env` через `python-dotenv` в dataclasses в `data/dataclasses/`
- API-эндпоинты определены в `data/endpoints.py`
- Кастомные ассерты в `utils/assertions/assertions.py` (сообщения об ошибках на русском)
- Генераторы тестовых данных на основе Faker в `utils/generators/base_generator.py`

**Конфигурация браузера (в conftest.py):**
- Chromium, viewport 1440x980, `headless=False`, `slow_mo=500ms`
- Фикстура `get_cookies` со scope=session кэширует куки авторизации
- Фикстура `authorized_user` со scope=function предоставляет преавторизованный контекст браузера

**Соглашения по тестам:**
- Каждый тест использует декораторы Allure: `@allure.feature`, `@allure.story`, `@allure.title`, `@allure.severity`
- Шаги тестов оборачиваются в `@allure.step()` или `with allure.step()`
- ID тестов указываются в заголовках (например, "TC-0001")

## Процесс создания нового теста

При создании каждого нового теста **обязательно** соблюдать следующий порядок:

1. **Ручное прохождение сценария в Chrome** — через Claude in Chrome открыть сайт и вручную пройти все шаги тестового сценария (заполнить формы, нажать кнопки, дождаться ответа). Зафиксировать: CSS-селекторы элементов, тексты сообщений, поведение страницы (редиректы, toast-уведомления, ошибки валидации и т.д.).
2. **Написание теста** — на основе собранных данных добавить необходимые локаторы в `locators/`, методы в page object в `pages/`, и сам тест в `tests/`. Следовать существующим соглашениям (Allure-декораторы, ID тест-кейса, allure.step).
3. **Проверка работоспособности** — запустить написанный тест через `pytest` и убедиться, что он проходит успешно. Если тест падает — исправить и перезапустить до зелёного результата.
4. **Обновление документации** — для каждого тестового файла `tests/test_<name>.py` должен существовать соответствующий файл `docs/test_<name>.md`. После написания или изменения теста — обновить документацию. Структура md-файла:
   - Каждый тест-кейс оформляется как отдельный заголовок `# TC-XXXX: Название теста`
   - Внутри — секции: **Severity**, **Шаги**, **Проверки**
   - Шаги и проверки описываются нумерованным списком

## Правила написания кода

При написании тестов **обязательно** руководствоваться следующими принципами:

- **DRY (Don't Repeat Yourself)** — не дублировать код. Если тесты отличаются только данными, использовать `@pytest.mark.parametrize` вместо копирования тест-функций. Для одинаковых сценариев по ролям (субадмин, менеджер, оператор) — всегда параметризация.
- **Page Object Model** — вся логика взаимодействия со страницей инкапсулирована в page-объектах. Тесты не содержат прямых обращений к локаторам или Playwright API.
- **Фикстуры** — если можно вынести подготовку данных или состояния в фикстуру, делать её в `conftest.py` и использовать в тестах.
- **Структура файлов по тест-сьютам:**
  - `locators/` — для каждого тест-сьюта отдельный файл с локаторами (CSS-селекторы, без логики)
  - `pages/` — для каждого тест-сьюта отдельный файл с набором функций, вся логика взаимодействия со страницей скрыта здесь
  - `pages/base_page.py` — базовые методы (click, fill, wait и т.д.), все page-объекты наследуются от него; новые общие методы добавлять сюда, существующие — переиспользовать
  - `tests/` — для каждого тест-сьюта отдельный файл с тестами
- **Данные:**
  - Эндпоинты — в `data/endpoints.py`
  - Переменные тестовых данных — в `data/dataclasses/`, для каждого тест-сьюта отдельный файл. В тестах не использовать хардкод — все значения хранить в переменных
  - Секретные данные (телефоны, пароли пользователей) — в `.env`, загружаются через `python-dotenv`
- **Ассерты** — кастомные ассерты хранить как функции в `utils/assertions/assertions.py`. Правило: **1 тест = 1 ассерт**

## Конфигурация

- `pytest.ini` — настройки обнаружения тестов, директория для Allure (`--clean-alluredir` очищает предыдущие результаты перед каждым запуском)
- `.env` — учётные данные (PHONE_NUMBER, PASSWORD); необходим для запуска тестов
